02 / The principle

The machine proposes. It never confirms.

Five promises shaped every screen.

01

Field by field

No “approve document” button.

02

Never overwrite

Every review is a new version.

03

Two clear states

Provisional never looks confirmed.

04

Point at the page

Verify any value in one click.

05

Humans leave no machine trace

Corrections drop confidence and highlight.

07 / Admin tools

Safe by design

Field names can’t be renamed, so history never breaks. Rules are built from kinds, never typed freehand.

Document types: new fields only append.
Validation rules: kind, condition, on/off.
08 / Validation

Failures are navigation

Each message names its fields. Click it, and you’re there.

RuleSeverityMessage
Invoice total reconciliationBlockingline_amount sums to 140 but total_amount is 5000
Line amount = qty × priceBlockingrow 0: 11 x 6 = 66, not 80
Invoice date not in futureCriticalinvoice_date is in the future: 2031-07-04
HSN code formatMilddoes not match: 3

Skipped is not a pass. A check that couldn’t run is shown, never hidden in “all green”.

09 / Honest limits

Designing the hard messages

No fake success, no lost work, no silent failures.

Upload: success only once processing starts.
Exceptions: no document is silently lost.
10 / Reflection

What this taught me

01

Trust is a UI problem

Show what the AI read and where, then let a person decide.

02

Silence is a signal

Hide high confidence so low confidence stands out.

03

Design the unhappy path

Conflicts, expiry and failures are daily, not edge cases.

Designing for AI meant designing for trust.
